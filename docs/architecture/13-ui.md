# 13 · UI

**Status:** Design standard (pre-1.0) · **Package:** `@ignifx/ui` · **Related:** `08-input.md` §5, `11-2d-toolkit.md` §2.7

Babylon Lite has no GUI system. ignifx's answer is deliberate: **game UI is HTML** layered over the canvas, and **in-world or pixel-HUD text** uses Lite's text renderer. HTML gives every game accessibility, fonts, layout, localization, and any framework the team already knows, in browsers and Electron alike.

---

## 1. Overlay host (`app.ui`)

- `app.ui.root`: an absolutely positioned `<div>` covering the canvas, `pointer-events: none` by default; children opt in with `pointer-events: auto`. Created by the extension; games mount React/Preact/Svelte/Vue/vanilla trees into it, or into named layers (`app.ui.layer("hud")`, `app.ui.layer("menu", { zIndex })`).
- Scaling modes: `"css"` (browser default), `"fit"` (scales the root to a reference resolution keeping aspect, for pixel-art HUDs), `"dpi"` (constant physical size). Safe-area insets are exposed as CSS variables.
- Focus routing: when an element inside the root receives keyboard focus, `app.input.uiHasFocus` is set; pointer events that reach `pointer-events: auto` elements are marked handled so gameplay actions ignore them.
- Visibility follows `app.ui.visible` and per-layer `visible`; the host hides itself in headless mode.

## 2. Components bridging world and DOM

- `WorldAnchor`: keeps a DOM element positioned at the entity's screen position (name tags, health bars, markers), with `offset`, `hideWhenBehindCamera`, `clampToScreen`, and `scaleWithDistance`. Updated in `PreRender` after camera sync, in batch, using `Camera.worldToScreen`.
- `WorldText` (3D) and `WorldText2D`: Lite `createTextRenderable` / text layers for text that belongs to the world (signs, damage numbers); fonts from `FontAsset` (`loadFont`); `text`, `fontSize`, `color`, `align`, `maxWidth`, `opacity`, `billboard`.
- `HudText`: pixel-space text through a Lite `TextRenderer` when DOM text is not desirable (e.g. capture-perfect pixel HUDs, screenshots via `captureScreenshot`).

## 3. Helpers

- `VirtualJoystick`, `VirtualButton` (touch controls feeding `@ignifx/input`'s virtual device).
- `Dialog`, `Toast` and `LoadingScreen` are plain DOM helper classes with no styling opinions beyond a minimal stylesheet; templates ship their own CSS.
- `Localization` (`app.i18n`) is a tiny key/value service with ICU-style plurals, loaded from `.json` assets; UI helpers and `WorldText` accept keys.

## 4. Non-goals

A retained-mode canvas GUI, data binding, or a UI editor. Teams that need canvas-drawn UI (e.g. inside a render texture) can use sprite layers and text layers directly.
