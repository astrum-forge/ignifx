# 05 · Assets and Loading

**Status:** Design standard (pre-1.0) · **Package:** `@ignifx/core` (service), loaders across extensions · **Related:** `06-serialization-and-scene-format.md`, `04-extensions.md`, Unity Addressables (inspiration)

---

## 1. Goals

- **Addressed, typed, reference-counted, asynchronous.** Assets are requested by address, return typed handles immediately, load asynchronously with progress and cancellation, and are released when the last holder lets go (Unity Addressables, not `Resources`).
- **Scenes pull their dependencies.** Loading a scene loads everything it references; unloading releases it.
- **One cache, one loader per type.** No duplicate GPU uploads for the same address; loaders are registered by extensions.
- **Works in browser, Electron, headless.** Same addresses everywhere; the manifest maps addresses to URLs or files.
- **Hot reload in development.** Editing an asset on disk swaps it in place.

## 2. Addresses

- An **address** is a string. By default it is a path relative to the project's asset root (`assets/` unless configured): `"models/hero.glb"`, `"sprites/hero.atlas.json"`. Absolute URLs (`https://…`), `blob:` and `data:` URLs are accepted as-is.
- An address may carry a **sub-asset fragment**: `"models/hero.glb#animation:Run"`, `"sprites/ui.atlas.json#frame:button_idle"`. Loaders define the fragment grammar for their type.
- The **manifest** (`assets.manifest.json`, generated by `@ignifx/vite-plugin`) maps addresses to hashed production URLs, byte sizes, content hashes, types, and **groups** (labels such as `"boot"`, `"level1"`). In development the plugin serves assets directly and the manifest is virtual.
- `AssetRef<T>` is the serializable form used in schemas and files: `{ "$asset": "models/hero.glb" }` (with optional `"type"` when it cannot be inferred from the extension). At runtime an `AssetRef` is a small frozen object `{ address, type? }` (serializable, no methods); `app.assets.load(ref)` loads it.

## 3. Handles

```ts
interface AssetHandle<T> {
  readonly address: string;
  readonly type: string;
  readonly state: "loading" | "loaded" | "failed" | "released";
  readonly value: T; // throws IGX-0501 unless state === "loaded"
  readonly promise: Promise<T>; // resolves with value, rejects with AssetLoadError
  readonly progress: number; // 0..1; bytes-weighted when sizes are known
  readonly error: AssetLoadError | null;
  readonly refCount: number;
  retain(): this; // +1
  release(): void; // -1; at 0 the asset is unloaded (after `assets.gcDelay`)
  [Symbol.dispose](): void; // == release(); enables `using`
  readonly onReplaced: SignalLike<T>; // hot reload delivered a new value; `value` already updated
}
```

- Handles are shared: two `load` calls for the same address and options return the same handle with `refCount` incremented. Each `load` must be paired with one `release`.
- Handles never become invalid objects; after release `state === "released"` and `value` throws.
- Scene loads hold handles on behalf of the scene instance and release them on unload. Components with `asset()` fields receive the handle already loaded and do not need to release it.

## 4. The `Assets` service (`app.assets`)

```ts
interface Assets {
  load<T>(ref: AssetRef<T> | string, options?: LoadOptions): AssetHandle<T>; // synchronous return, async completion
  loadAsync<T>(ref: AssetRef<T> | string, options?: LoadOptions): Promise<AssetHandle<T>>;
  loadAll(refs: readonly (AssetRef | string)[], options?: LoadOptions): BatchHandle;
  preloadGroup(group: string, options?: LoadOptions): BatchHandle; // manifest label
  get<T>(address: string): AssetHandle<T> | null; // no refcount change
  release(handleOrAddress: AssetHandle | string): void;
  gc(): void; // unload zero-ref assets now
  gcDelay: number; // seconds a zero-ref asset stays cached; default 5 (0 = immediate)
  resolveUrl(address: string): string;
  registerLoader(loader: AssetLoader): void; // normally via ExtensionContext
  readonly manifest: AssetManifest;
  readonly onProgress: SignalLike<{ loaded: number; total: number; bytesLoaded: number; bytesTotal: number }>;
}
interface LoadOptions {
  signal?: AbortSignal;
  priority?: number;
  type?: string;
  onProgress?: (p: number) => void;
}
interface BatchHandle {
  readonly promise: Promise<void>;
  readonly progress: number;
  readonly handles: readonly AssetHandle[];
  release(): void;
  cancel(): void;
}
```

- `load` returns immediately so that scripts can request in `awake` and check `state` later, or `yield handle.promise` in a coroutine.
- Requests are scheduled through a priority queue with a concurrency limit (default 6 concurrent fetches; configurable per platform). Cancellation via `AbortSignal` aborts the fetch and marks the handle `failed` with `AssetLoadError` code `IGX-0502` (aborted); refcounts still apply.
- Completed loads are delivered on the main thread in the `PreUpdate` phase of the next frame (never mid-phase), so `state` changes are observable at a consistent point. `promise` resolves at that time. While the app is not running — before `app.start()` and after `app.stop()` — there is no frame to wait for, so a completed load is delivered as soon as it finishes: a game can `await` its preloads and then start, and a headless test can `await` a handle without stepping. Retry backoff before `start()` runs on the wall clock for the same reason. (Amended 2026-09-06: the previous wording made a load awaited before `start()` wait forever.)

## 5. Loaders

```ts
interface AssetLoader<T = unknown> {
  readonly type: string; // "texture", "model", "scene", "audio", …
  readonly extensions: readonly string[]; // [".png", ".jpg", ".ktx2"]
  load(ctx: LoaderContext): Promise<T>;
  unload?(value: T, ctx: LoaderContext): void; // release GPU/audio resources
  reload?(ctx: LoaderContext, previous: T): Promise<T>; // hot reload; default = load the new value, then unload the previous
  parseFragment?(fragment: string, value: T): unknown; // "#animation:Run"
}
interface LoaderContext {
  readonly address: string;
  readonly url: string;
  readonly fragment: string | null;
  readonly type: string;
  readonly app: App;
  readonly signal: AbortSignal;
  fetchBytes(): Promise<ArrayBuffer>;
  fetchText(): Promise<string>;
  fetchJson<J>(): Promise<J>; // with progress + abort
  loadDependency<D>(ref: AssetRef<D> | string, options?: LoadOptions): Promise<AssetHandle<D>>; // counted against this asset
  reportProgress(fraction: number): void;
  readonly lite: { readonly engine: EngineContext }; // unstable escape hatch for Lite loaders
}
```

Core loaders (registered by the core extension):

| Type                     | Extensions                                        | Produces                                                                           | Notes                                                                                              |
| ------------------------ | ------------------------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `texture`                | `.png .jpg .jpeg .webp .ktx2 .basis`              | `TextureAsset` (wraps Lite `Texture2D`)                                            | Options via sidecar `.meta.json` (sRGB, mipMaps, filtering, premultiply); `.ktx2`/`.basis` below   |
| `model`                  | `.glb .gltf`                                      | `ModelAsset` (Lite `AssetContainer` template + node/animation/material index)      | `.glb` is fetched as bytes (progress, abort); `.gltf` with external files is passed as URL to Lite |
| `scene`                  | `.scene.json .prefab.json`                        | `SceneAsset` (validated file + resolved dependency handles)                        | Loads all referenced assets as dependencies                                                        |

| `mesh`                   | `.mesh.json`                                      | `MeshAsset` (one primitive: box, sphere, plane, ground, cylinder, capsule, torus)  | Same path as `MeshAsset.box(app)` and friends, which publish under this type too (ADR-0029)        |

### Compressed textures (amended 2026-10-19, engine ask E13)

One `texture` type covers six extensions, and the loader picks Lite's loader from the address's extension (the URL's when the address has none): `.png .jpg .jpeg .webp` go to `loadTexture2D` and the browser's image decoder, `.ktx2` to `loadKtx2Texture2D` and `.basis` to `loadBasisTexture2D`. Before, all six reached `loadTexture2D`, whose `createImageBitmap` fails on a KTX2 file. The Lite glue for the two compressed paths is in `src/lite/gpu/decoders.ts` and is imported on first use.

- **Transcode targets** are Lite's to choose; its public API has no override. They follow the device features `texture-compression-{astc,bc,etc2}`, which Lite requests whenever the adapter has them. ETC1S becomes ETC2 if `etc2` is present, else BC7 if `bc` is, else RGBA8. UASTC becomes ASTC 4×4 if `astc` is present, else BC7, else ETC2, else RGBA8. A Windows or Linux desktop gets BC7, Apple silicon gets ETC2 (ETC1S) or ASTC (UASTC), and a device without compression gets RGBA8. `.basis` uses Lite's own order: BC7, ASTC, ETC2, BC3, BC1, RGBA8.
- **Sidecar options.** `srgb` and the sampler (`addressModeU/V`, `minFilter`, `magFilter`) apply to `.ktx2`; `mipMaps` and `premultiplyAlpha` do not, since the file's own mip chain is uploaded as stored.
- **Orientation: rows as stored.** Block-compressed data cannot be flipped at upload, so `invertY` has no effect on a `.ktx2`: its first row lands at the top of the texture, as for a PNG with `invertY: false`. Lite 1.34 marks the handle `invertY`, but no material reads the flag, and a props-built PBR material ignores `setTextureTransform` (its UV-transform variant is enabled only by the glTF builder). A `.ktx2` meant to draw like its PNG under the default `invertY: true` is therefore **encoded from the vertically flipped image** (Basis `setYFlip(true)`). `packages/core/test/assets/ktx2.browser.test.ts` pins both cases.
- **Decoders.** Lite injects `babylon.ktx2Decoder.js`, which fetches `msc_basis_transcoder.{js,wasm}` (ETC1S), `uastc_*.wasm` (UASTC) and `zstddec.wasm` (Zstandard), and a glTF with `EXT_meshopt_compression` injects `meshopt_decoder.js`, all from `cdn.babylonjs.com` by default, which a packaged game's `script-src 'self'` refuses. `@ignifx/core` ships these eleven files (740 KB) in `decoders/` and lists them in its `ignifx.assets.public`, so `@ignifx/vite-plugin` serves and copies them like Havok's WASM (§7). Before a KTX2, Basis or glTF load, the loaders call `configureDecoders`, which hands Lite (`setKtx2DecoderUrl`, `setMeshoptBaseUrl`) the URLs of whichever of those files the manifest lists. A manifest without them keeps Lite's defaults; a project that builds without the plugin self-hosts by copying `node_modules/@ignifx/core/decoders/*` next to its assets and adding a manifest entry per file at its bare name. The files are vendored from `babylonjs-ktx2decoder` and `@babylonjs/ktx2decoder` 9.30.0 and `meshoptimizer` 1.3.0 by `pnpm vendor:decoders`, because those packages would pull Babylon.js into every game's install; `THIRD_PARTY_NOTICES.md` lists them. One file is edited on the way in: `msc_basis_transcoder.js` is an embind build that compiles four helpers from strings with `new Function`, which `script-src 'self' 'wasm-unsafe-eval'` refuses (`EvalError`, so no ETC1S texture loads); the script replaces each with an equivalent closure and marks the file as modified. Measured under that policy in headless Chromium: ETC1S to ETC2 and BC7 and UASTC to ASTC decode with no violation.
- **`.basis` still needs the CDN.** `loadBasisTexture2D` fetches `basis_transcoder.js` from `cdn.babylonjs.com/basisTranscoder/1/` and Lite 1.34 has no setter for it, so a `.basis` file does not load under `script-src 'self'`. Use `.ktx2`, which carries the same Basis payloads; a setter is an upstream ask.

Rules for loaders:

- Loaders are pure with respect to the world: they produce values, never create entities.
- GPU uploads happen inside `load` using the Lite engine; a loader must tolerate the null engine (return CPU-only data with `gpu: null`).
- Dependencies are loaded through `loadDependency` so that refcounts and progress propagate.
- Loaders must be idempotent per `(address, options)`; the cache guarantees single-flight.
- Loaders that produce materials report the material family (PBR feature bits, standard, shader) so the renderer can pre-register families before `registerScene` (`07-rendering.md` §1.1).

## 6. Instantiating models and prefabs

- A `ModelAsset` is a template. `Model` components (`07-rendering.md`) instantiate it under an entity by deep-cloning the Lite node tree (`cloneTransformNode`, sharing GPU buffers) and re-binding animation groups. Instances are counted so the template's GPU resources live until the last instance and the asset handle are gone.
- A `SceneAsset` is instantiated by the world (`02-scene-graph.md` §6).

## 7. Manifest and build integration

`@ignifx/vite-plugin`:

- Scans the asset root, emits `assets.manifest.json` with `{ address, url, bytes, hash, type, groups }`, fingerprints files, and copies them to `dist/assets/`.
- Reads `.meta.json` sidecars for per-asset import options and group membership (`{ "groups": ["level1"], "texture": { "srgb": true } }`). Every other key reaches the entry's `meta` unchanged, except two kinds (amended 2026-10-19): `"publish": false` leaves the asset out of the manifest, `dist/` and validation, in dev and in a build — an editor source whose imported output ships instead; and the editor-owned keys `guid`, `importer`, `source`, `outputs` and `options` (`EDITOR_SIDECAR_KEYS`), which describe an import rather than a load, never reach `meta`.
- Validates scene/prefab/material/atlas JSON against the generated JSON Schemas at build time (see `06-serialization-and-scene-format.md` §8).
- In development, watches the asset root and sends `ignifx:asset-changed` over Vite HMR; the assets service reloads affected handles and fires `onReplaced`. A change that arrives while a handle is still reloading runs one more reload after it, however many changes arrive meanwhile, and only the newest value is delivered (amended 2026-10-19: such a change used to be dropped). A failed reload keeps the value the handle had and reports an `IGX-0505` `AssetLoadError` with the address through `app.onError`.
- Handles WASM binaries listed by extensions (`ignifx.assets.public`) so Havok, Recast and, from `@ignifx/core`, Babylon Lite's KTX2 and meshopt decoders (§5, "Compressed textures") are served as static files and located via `resolveUrl`. Each one is copied **unhashed** and is also written into the manifest, at its bare file name, with the served URL and `base` applied (amended 2026-09-08): without an entry `resolveUrl` falls back to a page-relative `<assetRoot>/<address>`, which is right only when the document sits directly above the asset root and is `IGX-0903` anywhere else. A project asset whose address equals a published file name is `IGX-0552`. If the bundler emits its own byte-identical copy — `@babylonjs/havok`'s ESM build carries a dead `new URL("HavokPhysics.wasm", import.meta.url)` that Rollup resolves — the plugin repoints that reference at its own copy and drops the bundler's, so exactly one file ships. Discovery reads the packages installed **directly** in each `node_modules` from the Vite root upwards, so an extension reached only through the `ignifx` umbrella publishes nothing until the project depends on it by name.

Bundling many small files into packs (`.igxpack`) is a post-1.0 optimization; the manifest format reserves a `pack` field for it.

## 8. Platform notes

- **Browser:** addresses resolve under the app's base URL; production URLs are content-hashed and immutable-cacheable.
- **Electron:** the same manifest is used; files are read from the packaged app directory through the same `fetch` path (`file://` or a custom `ignifx://` protocol registered by `@ignifx/electron`), so loaders do not branch on platform.
- **Headless:** `fetch` is the only I/O path (a Node app passes a `fetch` that maps addresses to files); GPU-dependent loaders return CPU-side data.

## 9. Errors and diagnostics

- `AssetLoadError` carries `code` (`IGX-05xx`), `address`, `url`, `cause`. Network failures retry with exponential backoff (default 2 retries) unless aborted. Pending promises of an app that is disposed reject with `IGX-0503`.
- `app.diagnostics.assets` reports loaded count, bytes, in-flight requests, cache size, and zero-ref candidates.
