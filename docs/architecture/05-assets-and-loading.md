# 05 · Assets and Loading

**Status:** Design standard (pre-1.0) · **Package:** `@ignifx/core` (service), loaders across extensions · **Related:** `06-serialization-and-scene-format.md`, `04-extensions.md`, Unity Addressables (inspiration)

---

## 1. Goals

- **Addressed, typed, reference-counted, asynchronous.** Assets are requested by address, return typed handles immediately, load asynchronously with progress and cancellation, and are released when the last holder lets go (Unity Addressables, not `Resources`).
- **Scenes pull their dependencies.** Loading a scene loads everything it references; unloading releases it.
- **One cache, one loader per type.** No duplicate GPU uploads for the same address; loaders are registered by extensions.
- **Works in browser, Electron, headless.** Same addresses everywhere; the manifest maps addresses to URLs or files.
- **Hot reload in development.** Editing an asset on disk swaps it in place.

## 2. Addresses

- An **address** is a string. By default it is a path relative to the project's asset root (`assets/` unless configured): `"models/hero.glb"`, `"sprites/hero.atlas.json"`. Absolute URLs (`https://…`), `blob:` and `data:` URLs are accepted as-is.
- An address may carry a **sub-asset fragment**: `"models/hero.glb#animation:Run"`, `"sprites/ui.atlas.json#frame:button_idle"`. Loaders define the fragment grammar for their type.
- The **manifest** (`assets.manifest.json`, generated by `@ignifx/vite-plugin`) maps addresses to hashed production URLs, byte sizes, content hashes, types, and **groups** (labels such as `"boot"`, `"level1"`). In development the plugin serves assets directly and the manifest is virtual.
- `AssetRef<T>` is the serializable form used in schemas and files: `{ "$asset": "models/hero.glb" }` (with optional `"type"` when it cannot be inferred from the extension). At runtime an `AssetRef` is a small object `{ address, type? }` with `.load()` sugar.

## 3. Handles

```ts
interface AssetHandle<T> {
  readonly address: string;
  readonly type: string;
  readonly state: "loading" | "loaded" | "failed" | "released";
  readonly value: T;                    // throws IGX-0501 unless state === "loaded"
  readonly promise: Promise<T>;         // resolves with value, rejects with AssetLoadError
  readonly progress: number;            // 0..1; bytes-weighted when sizes are known
  readonly error: AssetLoadError | null;
  readonly refCount: number;
  retain(): this;                       // +1
  release(): void;                      // -1; at 0 the asset is unloaded (after `assets.gcDelay`)
  [Symbol.dispose](): void;             // == release(); enables `using`
  readonly onReplaced: Signal<T>;       // hot reload delivered a new value; `value` already updated
}
```

- Handles are shared: two `load` calls for the same address and options return the same handle with `refCount` incremented. Each `load` must be paired with one `release`.
- Handles never become invalid objects; after release `state === "released"` and `value` throws.
- Scene loads hold handles on behalf of the scene instance and release them on unload. Components with `asset()` fields receive the handle already loaded and do not need to release it.

## 4. The `Assets` service (`app.assets`)

```ts
interface Assets {
  load<T>(ref: AssetRef<T> | string, options?: LoadOptions): AssetHandle<T>;      // synchronous return, async completion
  loadAsync<T>(ref: AssetRef<T> | string, options?: LoadOptions): Promise<AssetHandle<T>>;
  loadAll(refs: readonly (AssetRef | string)[], options?: LoadOptions): BatchHandle;
  preloadGroup(group: string, options?: LoadOptions): BatchHandle;                // manifest label
  get<T>(address: string): AssetHandle<T> | null;                                 // no refcount change
  release(handleOrAddress: AssetHandle | string): void;
  gc(): void;                                   // unload zero-ref assets now
  gcDelay: number;                              // seconds a zero-ref asset stays cached; default 5 (0 = immediate)
  resolveUrl(address: string): string;
  registerLoader(loader: AssetLoader): void;    // normally via ExtensionContext
  readonly manifest: AssetManifest;
  readonly onProgress: Signal<{ loaded: number; total: number; bytesLoaded: number; bytesTotal: number }>;
}
interface LoadOptions { signal?: AbortSignal; priority?: number; type?: string; onProgress?: (p: number) => void }
interface BatchHandle { readonly promise: Promise<void>; readonly progress: number; readonly handles: readonly AssetHandle[]; release(): void; cancel(): void }
```

- `load` returns immediately so that scripts can request in `awake` and check `state` later, or `yield handle.promise` in a coroutine.
- Requests are scheduled through a priority queue with a concurrency limit (default 6 concurrent fetches; configurable per platform). Cancellation via `AbortSignal` aborts the fetch and marks the handle `failed` with `AssetLoadError` code `IGX-0502` (aborted); refcounts still apply.
- Completed loads are delivered on the main thread in the `PreUpdate` phase of the next frame (never mid-phase), so `state` changes are observable at a consistent point. `promise` resolves at that time.

## 5. Loaders

```ts
interface AssetLoader<T = unknown> {
  readonly type: string;                        // "texture", "model", "scene", "audio", …
  readonly extensions: readonly string[];       // [".png", ".jpg", ".ktx2"]
  load(ctx: LoaderContext): Promise<T>;
  unload?(value: T, ctx: LoaderContext): void;  // release GPU/audio resources
  reload?(ctx: LoaderContext, previous: T): Promise<T>;   // hot reload; default = unload + load
  parseFragment?(fragment: string, value: T): unknown;    // "#animation:Run"
}
interface LoaderContext {
  readonly address: string; readonly url: string; readonly fragment: string | null;
  readonly app: App; readonly signal: AbortSignal;
  fetchBytes(): Promise<ArrayBuffer>; fetchText(): Promise<string>; fetchJson<J>(): Promise<J>;   // with progress + abort
  loadDependency<D>(ref: AssetRef<D> | string): Promise<AssetHandle<D>>;   // counted against this asset
  reportProgress(fraction: number): void;
  readonly lite: { readonly engine: EngineContext };                       // unstable escape hatch for Lite loaders
}
```

Core loaders (registered by the core extension):

| Type | Extensions | Produces | Notes |
|---|---|---|---|
| `texture` | `.png .jpg .jpeg .webp .ktx2 .basis` | `TextureAsset` (wraps Lite `Texture2D`) | Options via sidecar `.meta.json` (sRGB, mipmaps, filtering, premultiply) |
| `model` | `.glb .gltf` | `ModelAsset` (Lite `AssetContainer` template + node/animation/material index) | `.glb` is fetched as bytes (progress, abort); `.gltf` with external files is passed as URL to Lite |
| `scene` | `.scene.json .prefab.json` | `SceneAsset` (validated file + resolved dependency handles) | Loads all referenced assets as dependencies |
| `material` | `.material.json` | `MaterialAsset` | PBR/Standard/Shader definitions |
| `environment` | `.env .hdr .dds` | `EnvironmentAsset` | IBL + optional skybox |
| `font` | `.ttf .otf` | `FontAsset` (Lite `Font`) | For world/HUD text |
| `json`, `text`, `binary` | `.json`, `.txt .md .csv`, `.bin .wasm` | parsed JSON / string / `ArrayBuffer` | Generic |

Extensions add: `audio` (`.mp3 .ogg .wav`; `@ignifx/audio`), `spriteatlas` (`.atlas.json` + image; `@ignifx/2d`), `tilemap` (`.tilemap.json`; Tiled `.tmj` and LDtk `.ldtk` are converted by `ignifx import tilemap` first; `@ignifx/2d`), `inputactions` (`.input.json`; `@ignifx/input`), `animator` (`.animator.json`; `@ignifx/3d`).

Rules for loaders:

- Loaders are pure with respect to the world: they produce values, never create entities.
- GPU uploads happen inside `load` using the Lite engine; a loader must tolerate the null engine (return CPU-only data with `gpu: null`).
- Dependencies are loaded through `loadDependency` so that refcounts and progress propagate.
- Loaders must be idempotent per `(address, options)`; the cache guarantees single-flight.
- Loaders that produce materials report the material family (PBR feature bits, standard, shader) so the renderer can pre-register families before `registerScene` (`07-rendering.md` §1.1).

## 6. Instantiating models and prefabs

- A `ModelAsset` is a template. `Model` components (`07-rendering.md`) instantiate it under an entity by deep-cloning the Lite node tree (`cloneTransformNode`, sharing GPU buffers) and re-binding animation groups. Instances are counted so the template's GPU resources live until the last instance and the asset handle are gone.
- A `SceneAsset` is instantiated by the world (`02-scene-graph.md` §6).

## 7. Manifest and build integration

`@ignifx/vite-plugin`:

- Scans the asset root, emits `assets.manifest.json` with `{ address, url, bytes, hash, type, groups }`, fingerprints files, and copies them to `dist/assets/`.
- Reads `.meta.json` sidecars for per-asset import options and group membership (`{ "groups": ["level1"], "texture": { "srgb": true } }`).
- Validates scene/prefab/material/atlas JSON against the generated JSON Schemas at build time (see `06-serialization-and-scene-format.md` §8).
- In development, watches the asset root and sends `ignifx:asset-changed` over Vite HMR; the assets service reloads affected handles and fires `onReplaced`.
- Handles WASM binaries listed by extensions (`ignifx.assets.public`) so Havok and Recast are served as static files and located via `resolveUrl`.

Bundling many small files into packs (`.igxpack`) is a post-1.0 optimization; the manifest format reserves a `pack` field for it.

## 8. Platform notes

- **Browser:** addresses resolve under the app's base URL; production URLs are content-hashed and immutable-cacheable.
- **Electron:** the same manifest is used; files are read from the packaged app directory through the same `fetch` path (`file://` or a custom `ignifx://` protocol registered by `@ignifx/electron`), so loaders do not branch on platform.
- **Headless:** `fetch` is used for URLs and Node file reads for paths; GPU-dependent loaders return CPU-side data.

## 9. Errors and diagnostics

- `AssetLoadError` carries `code` (`IGX-05xx`), `address`, `url`, `cause`. Network failures retry with exponential backoff (default 2 retries) unless aborted. Pending promises of an app that is disposed reject with `IGX-0503`.
- `app.diagnostics.assets` reports loaded count, bytes, in-flight requests, cache size, and zero-ref candidates.
