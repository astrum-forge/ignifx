# ADR-0019 · The public website: a prerendered static site on Cloudflare Pages

**Status:** Accepted · **Superseded in part by ADR-0020** (§1's "imports no workspace package", §2's "no inline script", §3's route list and the Consequences' "Impossible for now") · **Date:** 2026-09-06 · **Phase:** 12 · **Supersedes:** none
**Related:** `CONSTITUTION.md` §9.1 (no telemetry, no third-party requests), §11.1/§11.3 (licensing and attribution) · `docs/architecture/16-docs-harness-and-skill.md` §1 and §3 (the skill is the documentation; `llms.txt`) · `docs/plan/engineering-plan.md` Phase 12 · `website/DESIGN.md`

---

## Context

Phase 12 replaces the Phase 0 placeholder at `website/` with the real ignifx.com. Three constraints fix
almost everything about how it is built.

1. **The host is Cloudflare Pages, connected to this repository** (owner requirement, 2026-09-06).
   Cloudflare clones the repository, runs `pnpm install` at the root, then runs **one** build command,
   then serves a directory of files. There is no second step, no build orchestrator, no way to build a
   dependency first, and no server runtime.
2. **`CONSTITUTION.md` §9.1 forbids third-party requests.** No analytics, no CDN, no Google Fonts link.
   That is a rule about the engine and its templates, and it would be incoherent for the project's own
   site to break it.
3. **The site owes fixed URLs.** `website/public/llms.txt` is generated by `pnpm docs:llms` and
   publishes a URL for every page of the Agent Skill (`/skill/`, `/skill/<subsystem>/`,
   `/skill/references/<dir>/<name>`). Those URLs are a contract with agents; a page that 404s is a
   broken index.

A fourth constraint is a consequence of the first: at the moment Cloudflare runs the build, **no
`@ignifx/*` package has been built**. `turbo run build` is not available to the site, so the site
cannot import the engine, the Vite plugin, or the documentation harness in `scripts/`.

## Options considered

1. **A single-page application that fetches Markdown at runtime.** Cheapest to write. Rejected: the
   skill pages would not exist as URLs for a crawler or an agent that does not run JavaScript, and a
   fetch of the Markdown is exactly what `connect-src 'none'` is meant to prevent.
2. **A documentation framework (Astro, VitePress, Docusaurus).** Would give routing, search, and a
   theme for free. Rejected on three counts: each brings a large dependency tree that
   `CONSTITUTION.md` §9.3 would want justified; each imposes a visual system that
   `DESIGN.md` deliberately does not want; and each expects to own the whole site, which makes the
   "one command, no server" requirement a configuration exercise rather than a property of the build.
3. **Vite with an HTML entry per route.** Vite's multi-page mode needs a physical `.html` file per
   route — 68 of them, most generated. Rejected: the generator would have to write files into the
   source tree before the build, which is a second step in disguise, and Vite's HTML transform
   injects an inline module-preload polyfill that `script-src 'self'` refuses.
4. **Vite with JavaScript entries and a plugin that writes every page in `generateBundle`.** Chosen.

## Decision

### 1. One command, one Vite build, every page prerendered

`pnpm --filter @ignifx/website build` runs `vite build`, and the `ignifx-site` plugin
(`website/scripts/site.ts`) emits every route as `dist/<route>/index.html` from its `generateBundle`
hook, after Rollup has hashed the JavaScript and the stylesheet. There is **no HTML entry**: the two
Rollup inputs are `src/main.ts` and `src/theme.ts`, so Vite's HTML pipeline never runs and injects
nothing. `dist/404.html` is the not-found page, which Pages serves automatically.

The site reads the repository at build time — `AGENTS.md`, `benchmarks/baselines.json`,
`packages/core/package.json`, `packages/core/src/app/types.ts`, the template and example `README.md`
files, and every `SKILL.md` and reference page — and states nothing that is not in one of them. It
imports **no workspace package**, and it re-implements the `llms.txt` URL mapping rather than
importing `scripts/lib/llms-index.ts`, because neither is available in a fresh clone that has not run
`turbo run build`. The build fails when an `llms.txt` URL has no page, and `test/site.test.ts` asserts
the same thing over `dist/`, so the two copies of the mapping cannot drift apart silently.

### 2. No inline script and no inline style, enforced by the CSP

`website/public/_headers` ships
`default-src 'self'; img-src 'self' data:; script-src 'self'; style-src 'self'; font-src 'self'; connect-src 'none'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'`
with no `unsafe-inline` on either script or style. Two things follow, and they are the reason the
build looks the way it does:

- **Shiki cannot write its colours as `style` attributes.** The build tokenizes instead of rendering,
  interns each light/dark colour pair as a class, and emits those classes into a real stylesheet.
- **The theme cannot be applied by an inline script**, which is the usual way to avoid a flash of the
  wrong theme. `/theme.js` is a real file, deliberately unhashed and import-free, loaded
  synchronously in `<head>`.

`connect-src 'none'` means the page makes no network request of its own: the search index is loaded
by appending a `<script>` element, which `script-src 'self'` governs, not `fetch`.

### 3. Fonts are npm packages, self-hosted, latin only

Three `@fontsource-variable/*` packages are website devDependencies with catalog pins
(`pnpm-workspace.yaml`). Only the latin weight-axis `woff2` of each is copied into the build —
Archivo 34,928 B, Public Sans 26,832 B, JetBrains Mono 40,404 B, **102,164 B** in total against a
120 KB budget — with `font-display: swap`, a `size-adjust` fallback face measured in Chromium, and
each face's SIL Open Font Licence copied to `/licenses/` and linked from the footer
(`CONSTITUTION.md` §11.3).

### 4. The no-third-party rule is a test, not a promise

`website/test/site.test.ts` scans every emitted HTML file for a `link`/`script`/`img`/`source`/media
element whose `href` or `src` leaves the origin, scans every emitted stylesheet for an off-origin
`url()` or `@import`, and fails on an inline `<script>`, a `<style>` element, a `style` attribute, or
an `on*` handler. It also checks that every internal link resolves to a file in `dist`, that
`sitemap.xml` lists every prerendered route, that `_headers` and `_redirects` parse, that every page
has one `<h1>`, landmarks, a skip link and a language, that every image carries alt text and an
intrinsic size, and that every token pair in `DESIGN.md` clears WCAG AA in both themes.

### 5. Page weight is budgeted, with two recorded exceptions

Every route is at most 120 KB gzipped for HTML + CSS + JS. Two are not, and cannot be: the generated
API reference for `@ignifx/core` and for the `ignifx` umbrella are 609 KB and 1.6 MB of Markdown,
which gzip to 139 KB and 313 KB before a single tag is added. They are still served in full, because
`llms.txt` publishes their URLs; above 250 KB of source a page ships uncoloured code and no
per-heading permalink anchors, and its weight is pinned in the test so it cannot grow unnoticed.

### 6. CI checks, Cloudflare deploys

`.github/workflows/website.yml` regenerates `llms.txt` and fails on a diff, typechecks, builds, runs
the website tests, and uploads `dist` as a workflow artifact. It does **not** deploy: Cloudflare Pages
does that from `main`. The GitHub Pages job that Phase 0 used as a placeholder is removed.

## Consequences

**Easier.** Adding a page is adding a function and a route. Adding a skill page is adding a Markdown
file to `skills/` — discovery, the rail, the pager, the search index and the sitemap all follow. The
security posture is testable rather than aspirational, and the whole site is 93 files with no runtime.

**Harder.** There is no client-side router, so any new URL must be a prerendered file, and any alias
must be a `_redirects` line. Anything that would need a request at runtime — a contact form, a
comments widget, live search over a remote index — is out of reach without changing the CSP and this
ADR. Rendering is a Rollup `generateBundle` hook, so a page render error surfaces as a plugin error
rather than as a broken page.

**Impossible for now.** Live engine demos on the marketing pages. The site is WebGPU-free by
construction: it would otherwise have to import a built `@ignifx/*` package, which Cloudflare does not
have. The gallery shows the visual suite's golden captures instead.

**How to revisit.** If a live demo becomes worth it, the cheapest change is to build the demo bundle
in CI and commit its output under `website/public/`, leaving the one-command property intact. If that
is not enough, the next step is a Cloudflare build command that runs two commands, which the owner
requirement excludes today and which a superseding ADR would have to state.
