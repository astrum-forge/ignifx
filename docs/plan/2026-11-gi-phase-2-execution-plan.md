# Plan · GI Phase 2 "Baked lighting run time": execution plan

**Status:** Done (2026-11-09): B1–B6 merged, follow-ups in §7 · Proposed 2026-11-04 · **Owner:** Astrum Forge Studios · **Precedence:** below constitution, standards, architecture docs, ADRs (`CONSTITUTION.md` §10.1) · **Parent:** [`2026-10-global-illumination-feasibility.md`](2026-10-global-illumination-feasibility.md) §3.6 (option E), §5 Phase 2, decisions in its §8

Phase 2 is the engine half of option E: reflection probes, light probes and lightmaps at run time, plus the smallest bake the engine can do on its own. The editor's baker (UV2 unwrap, GPU path tracer, denoiser, bake panel) waits for editor 0.8 or later (feasibility §8.4), so every format here is plain JSON plus textures that a later baker writes and that a game can author by hand or with the B4 baker today. This document records what Lite 1.34 gives and lacks (§2), the rules (§3), the steps B1–B6 (§4), two spikes (§5) and what is still unverified (§6).

Lite claims cite `@babylonjs/lite@1.34.0` (`index.d.ts`, `lib/`), the pinned version. The feasibility doc estimates the run time at 10–14 agent-days.

## 1. Scope

In: reflection probes, light-probe volumes, lightmaps, a CPU light-probe bake in core, quality-tier presets, goldens, schemas and skill pages. Out: the editor baker and its lightmap bake (§8.4 there), SSR and dynamic diffuse GI (Phase 3), probe streaming.

**Not supported by Lite 1.34** (each step works around it as stated):

- ✗ **Cube capture, prefiltering and SH projection.** No public function renders a cube from a point or turns a rendered cube into `EnvironmentTextures`; the loaders take files only (`loadEnvironment` 7802, `loadDdsEnvironment` 7779, `loadHdrEnvironment` 7870). B1 renders six faces and builds the mip chain itself, box-filtered rather than GGX-prefiltered.
- ✗ **Light probes / SH irradiance volumes.** Nothing exists. The IBL fragment declares `environmentIrradiance` with `let` (`lib/material/pbr/fragments/ibl-fragment.js`), so a plugin cannot replace it; it can only add a correction to `color` before final composition (spike P1).
- ✗ **Lightmap UV transform.** The lightmap fragment samples `input.uv2` raw (`lib/material/pbr/fragments/lightmap-fragment.js` line 24), ignoring `Texture2D.uScale`/`uOffset` (14956) and `cloneTexture2D` (1906), so per-renderer atlas scale and offset need spike P2.
- **Mesh filters per pass (partly).** `RenderTaskConfig` has no layer field, but `autoMirror: false` (11695) with `addMeshToTask`/`removeMeshFromTask` (126, 11363) and `enableRenderTaskMeshRefresh` (5357) gives a task an explicit render list. B1 hides rejected meshes around the task's `execute` instead, as `render-texture.ts` does for editor-only meshes; an explicit list is the option if that costs too much.
- ✗ **3D textures in plugins.** Plugins bind 2D textures only, so probe volumes are packed into a 2D array.

## 3. Rules for every step

- **One PR per step, ≤1 agent-day.** If a step overruns, ship the core slice and list the rest under "Remaining" in the PR.
- **Pay for use (`CONSTITUTION.md` §2.5).** Each GPU path is its own module under `packages/core/src/lite/gpu/`, reached by a dynamic `import()` only when a component or asset of its kind exists, as Phase 1's chunks are. A project with no probe, volume or lightmap loads none of it and has no extra frame work.
- **The editor gets it through schemas.** Components declare tooltipped schemas; `.probes.json` and `.lightmap.json` get file-format schemas in `src/render/schemas.ts`; `pnpm docs:schemas` regenerates what the inspector renders.
- **Gate (owner rule, 2026-11-03).** `pnpm check --only build,typecheck,lint`, `pnpm deps`, CI green with core's 90% branch floor. At most one small unit file per step, for pure logic (selection, parsing, SH math); one browser test per GPU step. Goldens are recorded by the coordinator in bulk after B3.
- **Docs in the same PR.** TSDoc, `api/*.api.md`, a skill page, and a `minor` changeset for new public API (§4.5).

## 5. Spikes (half a day each, throwaway branch, like Phase 1's S1–S4)

- **P1** (before B2) A PBR plugin at `CUSTOM_FRAGMENT_BEFORE_FINALCOLORCOMPOSITION` that reads `environmentIrradiance`, `surfaceAlbedo` and `occlusion` and adds the probe correction to `color`, with and without the S1 linear-output plugin, and with GTAO's plugin on the same material.
- **P2** (before B3's scale/offset) Whether a vertex plugin (`CUSTOM_VERTEX_MAIN_END`) can rewrite the UV2 varying the lightmap fragment reads; if not, a renderer's UV2 is rewritten into atlas space when its mesh is cloned, or each renderer gets its own texture.

## 6. Not verified

- Cube-face orientation against Lite's cube sampling (`rotateY(R, scene.envRotationY)`, left-handed): B1's browser test (#151, green in CI) shows a mirror reflecting the walls behind the camera on the correct left/right sides, with HDR off and on. The ±Y faces and a rotated environment are not checked.
- `enablePbrLocalCubemap` after `registerScene`: Lite says to call it before. B1 calls it when the first probe appears and rebuilds the affected materials, and that worked in the same browser test; device loss on that path was not tried.
- Box-filtered mips under rough materials: blurrier and blockier than a prefiltered `.env`. With `rendering.hdr` off the captured colour is tone-mapped and gamma-encoded, and B1 only undoes the gamma.
- No Phase 2 cost has been measured; every budget above is an estimate, and `everyFrame` capture is 6 extra scene passes.
- Whether `world.raycastRender` hits anything in a headless Node app (cloned meshes need a device); B4 is specified for an app with one.
- Safari 26 and Firefox were not tried.

**Remaining**

- **B1b, reflection-probe blending:** one `createPbrLocalEnvironmentProbeSet` for overlapping probes, a GGX prefilter instead of box mips, `ReflectionProbe.blendDistance` and `capture()` to a file.
- **Spike P2, the lightmap atlas transform:** `.lightmap.json` `entries` other than the identity log `IGX-0735` and sample the whole texture until UV2 can be rewritten into atlas space.
- **The lightmap baker:** UV2 unwrap (`xatlas` as WebAssembly, an ADR under §9.3) and a GPU path tracer, in the editor's baker (feasibility §8.4); the engine bakes light probes only.
- **Goldens:** one visual golden per B1–B3 scene is not recorded yet (coordinator bulk run), and no Phase 2 cost has been measured with `pnpm test:gpu-budget` on a scene that captures.
- **The template `.env` decision (owner):** the 3D templates add a `ReflectionProbe` at `high` (#163) but load no environment map, so it stays idle; making it visible means shipping `studio.env` (205 KB) and a BRDF table, which changes the `high` look and its goldens.
- §6's unverified items stand: ±Y faces and a rotated environment, device loss of the probe path, Safari and Firefox.
