# Plan · GI Phase 1 "Foundations": execution plan

**Status:** Proposed (2026-11-02) · **Owner:** Astrum Forge Studios · **Precedence:** below constitution, standards, architecture docs, ADRs (`CONSTITUTION.md` §10.1) · **Parent:** [`2026-10-global-illumination-feasibility.md`](2026-10-global-illumination-feasibility.md) §5, decisions in its §8

Phase 1 delivers the HDR and temporal base every GI option needs, plus most of the "Unreal look": an HDR scene path, TAA with motion vectors, cascaded-shadow knobs, GTAO, contact shadows and Lite's SSGI in `PostProcessStack`, HDR bloom, AgX and auto exposure, and a written GPU budget per quality tier. This document records spikes S1–S4 (§2), the rules every step follows (§3), the upstream asks (§4), the steps G1–G16 (§5) and what is still unverified (§6).

Lite claims cite `@babylonjs/lite@1.34.0` (`index.d.ts`, `lib/`), the pinned version.

## 1. Scope

In: the §5 Phase 1 row of the feasibility doc. Out: reflection probes, SSR, lightmaps and probes (Phase 2), SDF probe GI (Phase 3), PCSS and area lights (upstream, §4).

## 3. Rules for every step

- **One PR per step, ≤1 agent-day.** If a step overruns, ship the core slice and list the rest under "Remaining" in the PR.
- **Pay for use (`CONSTITUTION.md` §2.5).** Each effect lives in its own module under `packages/core/src/lite/gpu/` (Lite calls) with a thin record in `src/render/`, reached by a dynamic `import()` only when its record is enabled — the pattern of `src/render/post-effect-support.ts` line 85 and `src/lite/render-features.ts` line 141. The step's PR shows the template entry chunks unchanged in `benchmarks/bundle-size.test.ts`.
- **The editor gets it through schemas, with no editor work.** New effect settings are records on `PostProcessStack.schema` (`src/render/post-process-stack.ts` line 570, one record per effect, as its module comment explains), shadow knobs are fields on the `Light` schema (`src/render/light.ts` line 601), project-wide switches go in the `rendering` settings schema (`src/render/rendering-settings.ts` line 196). Every field has a tooltip; `pnpm docs:schemas` regenerates the JSON schemas the editor's inspector and project settings render.
- **Tests.** Headless unit tests for schema defaults and option mapping (`node` project); one browser test per step on SwiftShader that reads back pixels or floats as the spikes do; one visual golden scene per visible effect under `tests/visual`, run locally only with before/after images in the PR (coding standards lines 245, 264); the step's GPU cost from G1's `gpu-budget` project pasted in the PR.
- **Docs in the same PR.** TSDoc, `api/*.api.md`, `skills/ignifx` rendering pages, `docs/architecture/07-rendering.md` §2.7, and a `minor` changeset for new public API (`CONSTITUTION.md` §4.5).

## 4. Upstream Lite asks (minimal repro text, for the coordinator to file)

1. **Linear HDR output.** Render a PBR sphere (white, roughness 1) lit by `createHemisphericLight([0,1,0], 8)` into an `rgba16float` render target; the centre texel reads `1.0`, because `pbr-template.js` line 171 tone maps, gamma-encodes and clamps every fragment. Ask: a scene or material switch that leaves output linear and unclamped so one final pass tone maps. Workaround: spike S1 (loses fog; one plugin per material).
2. **One post-composition plugin point.** `CUSTOM_FRAGMENT_BEFORE_FINALCOLORCOMPOSITION` is injected at both `/*AI*/` and `/*NI*/` (`plugin-bridge-shared.js` line 13); `let x = color;` there fails as a redeclaration. Ask: document it, or add a single point after all composition and before fog.
3. **Geometry attachments as `Texture2D`.** `createGeometryRendererTask` exposes attachments only as `RenderTarget`s (`index.d.ts` 6372–6397), and compute binds only `Texture2D`s (`createComputeTextureResource`, 2810); reading world normals in compute needs a full-screen copy (spike S2). Ask: a sampled facade per attachment, or external colour targets per `textureDescriptions` entry.
4. **TAA for a moving camera.** `createTaaPostProcessTask` with `disableOnCameraMove: false` and a camera orbiting every frame: history is not reprojected and no velocity is read (`lib/post-process/taa.js` lines 76, 105). Ask: velocity reprojection with neighbourhood clamping, or a public projection-jitter helper.
5. **Soft shadows.** CSM filtering is a fixed 5×5 PCF (`lib/shadow/csm-directional-shadow-generator.js` line 15). Ask: PCSS or contact-hardening option.
6. **Area lights.** No rect or disc light type exists. Ask: LTC area lights.

**GPU budget (written into coding standards §7 by G1).** At 1080p, all Phase 1 passes together, including the G4 geometry pass:

| Tier     | Devices                                           | Phase 1 passes                                                                                                | Whole frame |
| -------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ----------- |
| `low`    | phones, integrated GPUs on battery                | ≤ 1.5 ms on the reference M1: GTAO at half resolution, LDR or HDR bloom, AgX; no TAA, SSGI or contact shadows | ≤ 12 ms     |
| `medium` | integrated GPUs (reference: Apple M1)             | ≤ 4 ms on the M1: adds HDR, TAA, contact shadows                                                              | ≤ 12 ms     |
| `high`   | mid-range desktop GPUs (RTX 3060 / RX 6600 class) | ≤ 3 ms: adds SSGI and full-resolution GTAO                                                                    | ≤ 10 ms     |

The numbers start from the feasibility doc's estimates (§3.7 there). G1 checks them on the M1 and G15 records what was measured. Dynamic GI (Phase 3) gets its own `high`-only line later.

## 6. Not verified

- Whether Lite lets ignifx jitter the camera projection without forking its camera code (G5); it was not checked.
- Linear output for Standard materials, surface shaders, sprites, particles and the skybox (S1 tested PBR only); fog under HDR (G3).
- Device-loss recovery for `rgba16float` targets and compute resources; Lite does not recover writable storage buffers (`index.d.ts` 14536–14541).
- Cost: the spikes measured one sphere at 512×512 (0.125 ms scene task on the M1). No Phase 1 effect has been timed, and no mid-range desktop GPU is available locally, so the `high` row is unchecked.
- MSAA with an `rgba16float` target was not tried; the spikes used single-sample targets.
- Safari 26 and Firefox were not tried.
